# Working Reports

Working reports are one-time or campaign-specific review artifacts. They are
useful while making a decision, migrating services, or cleaning up a class of
issues, but they are not durable source-of-truth files.

Use this section for subjective output that does not belong in a boolean
validator:

- migration review notes
- cleanup recommendations
- architecture or documentation quality snapshots
- temporary gap lists for an active campaign

Keep reports concise and date-aware. A report should say what it reviewed, what
is source-of-truth evidence, what is human judgment, and what can be deleted
after the follow-up work is done.

Do not use reports to duplicate app-owned documentation, generated service
catalog data, runtime config, secrets policy, or deployment procedures. Link to
those sources instead.
