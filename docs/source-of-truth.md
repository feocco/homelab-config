# Homelab Sources Of Truth

This page maps the homelab by engineering domain. File paths and scripts are
implementation details under those domains, not the taxonomy itself.

## Services

The strongest modeled object is the runtime service.

- Durable service intent lives in `services/<service>/ops.yaml`.
- Host placement lives in `hosts/<host>/services.yaml` as a service facet.
- Compose shape lives beside each service in `services/<service>/docker-compose.yml`.
- Generated service inventory comes from `./scripts/generate-service-catalog`
  and `./scripts/list-homelab-services`.
- Homepage service tiles come from `dashboard_*` fields in `ops.yaml`.

Gap: service ownership is clear, but app-level API contracts and domain data
models are still mostly in each app repo.

## Networking

Networking truth is declared from service intent, then rendered into runtime
proxy and DNS config.

- Active HTTPS routes live as `route_*` fields in service `ops.yaml` files.
- Retired route redirects live in `services/caddy/retired-routes.yaml`.
- Caddy runtime config is generated by `./scripts/generate-caddy-config`.
- UniFi LAN DNS and Cloudflare Tailnet DNS are reconciled with
  `./scripts/sync-unifi-dns` and `./scripts/sync-cloudflare-dns`.
- Private/public split-horizon services are the public internet access pattern
  for services that should work without Tailscale: public Cloudflare
  Tunnel/Access DNS is the off-LAN source of truth, while UniFi DNS is the LAN
  override. Mealie is the reference implementation.
- The route model is documented in `services/caddy/README.md`.

Gap: Caddy output and DNS provider state are generated/runtime state, not source
of truth. Use validation and sync commands to detect drift.

## Infrastructure

Infrastructure is split between host manifests and service definitions.

- Host roles and placement are in `hosts/*/services.yaml`.
- Shared infrastructure services such as Caddy, Homepage, Homelab Monitor,
  Portainer, Pi-hole, and Mealie live under `services/`.
- `docs/overview.md` gives the high-level architecture.
- `docs/deployment-source-of-truth.md` defines what production deploy state
  means.

Gap: host inventory is intentionally lightweight. Device-level network inventory
is not yet centrally modeled here.

## Observability

Observability combines monitoring config, dashboards, and service metadata.

- Prometheus scrape targets live in
  `services/homelab-monitor/prometheus/prometheus.yml`.
- Grafana dashboards live in `services/homelab-monitor/grafana/dashboards/`.
- Blackbox probe config lives in `services/homelab-monitor/blackbox/`.
- Smoke Signal targets are generated during `homelab-functions` deploy from the
  service catalog into `services/homelab-functions/config/`.
- SRE issue/autofix metadata lives in `services/homelab-sre-agent/services.yaml`.
- Homepage `siteMonitor` dots are UI hints only; Grafana and Prometheus remain
  the monitoring evidence source of truth.

Gap: Grafana cannot alert if the Mac mini Docker stack is down. The NAS
Smoke Signal covers that broad-outage phone alert only; it is not a metrics
store.
Monitoring coverage and SRE coverage remain related but separate.

## Data And API Domains

Data/API domain truth is currently app-local.

- Plant domain data has a local deployment input at
  `services/plant-monitor/plants.yaml`.
- Bedtime has local service config at `services/bedtime/config.yaml`.
- App APIs and event descriptions usually live in the app repo named by each
  service's `source_repo`.
- `homelab-functions` is the central notification and homelab API service.

Gap: there is no central data catalog for app APIs, events, or domain objects.
This is the main future-state opportunity.

## Secrets

Secrets are service metadata plus operational workflow, not a standalone
catalog.

- Required secret names live in `service-secrets.yaml`.
- GitHub Actions deploy secret wiring is generated by
  `./scripts/generate-service-secret-workflow-env`.
- Secret validation runs through `LC_ALL=C ./scripts/check-service-secrets`.
- Real `.env` files and runtime secret values must not be committed.

Gap: the repo knows required secret names and wiring, but not secret values,
rotation state, or a central external secrets manager.

## Runtime Evidence

Runtime evidence proves what happened, but does not replace git.

- `homelab-config/main` is durable production truth.
- GitHub Actions runs show deploy execution history.
- `./scripts/validate-service-rollout` checks config and live rollout proof.
- `./scripts/homelab-deploy` writes ignored deploy provenance under
  `.homelab-deploy-state/`.
- `docs/deployment-source-of-truth.md` defines canary, dirty, and emergency
  deploy semantics.

Gap: runtime state can drift from source. Treat deploy provenance, live checks,
and provider consoles as reconciliation inputs, not durable intent.
